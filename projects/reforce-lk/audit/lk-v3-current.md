## Что реализовано

| Раздел | Экраны |
|---|---|
| Объект | Карточка объекта (статус, индикаторы, разделы), постановка/снятие, тревожная кнопка, устройства |

| Профиль | Имя, телефон, почта, Безопасность (PIN + биометрия) |

## UX-проблемы

### Критичные

| # | Проблема | Экран | Влияние |
|---|---|---|---|
| C1 | PIN вводится в текстовое поле, не PIN-пад | Постановка/снятие | Низкий UX, нет haptic, цифры видны |
| C2 | Тревожная кнопка — большая розовая карточка без защиты от случайного нажатия | Объект | Риск ложных вызовов |
| C3 | События написаны техническим языком: «Пропущенное отключение сети 220в» | Лента событий | Виктор (45+) не поймёт |
| C4 | Половина событий — серая иконка «?», нет классификации | Лента событий | Непонятно: важно или нет |

### Значимые

| # | Проблема | Экран |
|---|---|---|
| S1 | Красный цвет = статус + кнопки + баланс + тревога + тогглы — всё красное, нет иерархии сигналов | Везде |
| S2 | Отрицательный баланс «-795 р.» — большая красная карточка, вызывает тревогу вместо спокойного «пополните» | Платежи |
| S3 | «Уведомления о событиях» и «Отчёты по событиях» — идентичные экраны с одинаковыми 9 тогглами, разница непонятна | Параметры |
| S4 | Список пользователей без ролей и без кнопки «Добавить» | Параметры |
| S5 | Системные индикаторы (Батарея !, Сеть 220 !) — красные иконки без объяснения и без CTA | Объект |
| S6 | Серые иконки (Пожарная система, Контроль взлома) — непонятно: ОК или неизвестно? | Объект |

### Мелкие

|---|---|
| M1 | Опечатка: «Системные сообщение» → «сообщения» |

## Что сделано хорошо (сохранить в новом дизайне)

- Bottom sheet для постановки/снятия — правильный паттерн
- Выбор разделов + «Снять весь объект» по умолчанию — логично
- «Подтвердить» задизейблен до ввода кода — защита от ошибки
- Биометрия уже есть (Face ID / Touch ID) — закрывает gap конкурентов
- Вкладки «Информация» / «События» на объекте — разумное разделение
- Поддержка → «Обучение» — правильная идея онбординга внутри приложения
- Поиск по договорам на экране платежей

## Выводы для нового дизайна

1. **Главное действие** (постановка/снятие) сделать главным визуально — не карточка внизу, а центр экрана
2. **PIN-пад** вместо текстового поля
3. **Тревожная кнопка** — убрать с основного скролла, добавить подтверждение
4. **Язык событий** переписать: «Свет отключился → резервное питание включилось» вместо технических кодов
5. **Красный** только для тревог и критичных состояний; нейтральные действия — не красные
6. **Баланс** — нейтральный цвет + понятный CTA «Пополнить», не красная карточка
7. **Пользователи** — роли видны в списке, есть кнопка «Пригласить»
