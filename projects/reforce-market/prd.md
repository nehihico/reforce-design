# PRD: Маркет Reforce — функциональные требования

**Версия:** 1.0 (май 2026)  
**Контекст:** `brief.md` | **Проблемы и метрики:** `problems.md`  
**User flow:** `projects/reforce/ia/user-flows.md` → UF-SHOP

---

## Приоритеты

- **Must** — без этого продукт не работает
- **Should** — важно, но можно во 2 итерации
- **Could** — желательно при наличии ресурса

---

## 1. Главная страница

| Требование | Приоритет |
|---|---|
| Hero: заголовок + преимущества + CTA «Подобрать комплект» как первичный | Must |
| Персонализация по городу: геолокация браузера + ручной выбор | Must |
| Квиз «Подберите решение» как основной путь конверсии | Must |
| Блок «Как это работает» — 4 шага до охраны | Must |
| Социальное доказательство: 50 000+ объектов, 96% SLA, 85% NPS | Must |
| Изображения без людей в форме, камер и щитов | Must |
| «Популярные решения» — 3 категории | Should |
| Отзывы клиентов | Should |

---

## 2. Квиз — подбор комплекта

| Требование | Приоритет |
|---|---|
| Шаг 1: тип объекта (Квартира / Частный дом / Бизнес / Гараж и дача) | Must |
| Шаг 2: уточнение (от ограбления / пожар / видеонаблюдение / умный дом) | Must |
| Шаг 3: ≤ 3 пакета с уникальными названиями и чёткой дифференциацией | Must |
| Каждый пакет: название, абонплата, стоимость оборудования, состав | Must |
| Один рекомендованный пакет с badge | Must |
| CTA «Подробнее» → карточка | Must |
| CTA «Оформить» → форма заявки | Must |

---

## 3. Карточка товара

| Требование | Приоритет |
|---|---|
| Название, цена (абонплата + оборудование раздельно и суммарно) | Must |
| «Что входит» — список оборудования | Must |
| «Что вы получите» — выгоды, не характеристики | Must |
| CTA «Оформить подключение» — sticky на десктопе, fixed bottom на мобайле | Must |
| «Путь к охране за 24 часа» — шаги после заявки | Must |
| Работаем в вашем городе + статистика | Should |
| Сравнение с другими пакетами | Should |
| FAQ — 5-7 вопросов | Should |
| Отзывы с рейтингом | Should |
| Кнопка «Обратный звонок» | Should |
| Кнопка «Поделиться» | Could |

---

## 4. Форма заявки (UF-SHOP)

| Требование | Приоритет |
|---|---|
| Авторизация через OIDC (единая с ЛК) если не залогинен | Must |
| Прогресс-бар по шагам формы | Must |
| Шаг — адрес объекта: карта + ввод вручную | Must |
| Шаг — выбор существующего объекта (из ЛК) или нового | Must |
| Шаг — форма собственности | Must |
| Шаг — контактные данные (подтягиваются из профиля) | Must |
| Шаг — ответственные лица | Must |
| Шаг — согласие на обработку данных (152-ФЗ) | Must |
| Выбор пути: самостоятельно → оплата / через менеджера → звонок | Must |
| Шаг — промокод (опционально) | Should |
| Шаг — прикрепление документов | Should |
| Сохранение черновика при закрытии страницы | Should |

---

## 5. Раздел «Заявки»

| Требование | Приоритет |
|---|---|
| Список заявок с текущим статусом | Must |
| Карточка заявки: состав, статус, ожидаемая дата монтажа | Must |
| Редактирование анкеты если требуются правки | Must |
| После монтажа объект появляется в ЛК | Must |
| Отмена заявки | Should |

## 7. Интеграции

| Система | Назначение | Статус |
|---|---|---|
| OIDC | Единая авторизация с ЛК | В работе |
| Яндекс.Карты / 2GIS | Адрес объекта при оформлении | Нужен выбор |
| CRM / 1С | Передача заявки в работу | Существующая |
| Платёжный шлюз | Оплата при оформлении заявки | Не выбран |
| Яндекс.Метрика | Аналитика и конверсии | Нужна настройка |
