## DEC-001: Не показывать push при ложных тревогах

**Дата:** —  
**Связь с PRD:** SEC-14, UF-09  
**Решение:** Push отправляется только когда ГБР реально направлена. При ложных тревогах — запись в ленте событий без уведомления.

**Обоснование:**  
90%+ срабатываний — ложные. Если слать push на каждое, пользователь привыкнет игнорировать. Настоящее уведомление потеряет вес. Цель — push должен восприниматься серьёзно.

**Альтернативы рассматривались:**  
- Отправлять все пуши: риск выгорания уведомлений ❌  
- Отправлять с пометкой «ложная тревога»: противоречит UX-принципу «без паники» ❌

## DEC-002: Язык уведомлений — без технических терминов

**Дата:** —  
**Связь с PRD:** UF-09, UX-принципы  
**Решение:** Вместо «тревога, шлейф 3, зона B» → «Направили группу реагирования на ваш объект [название]».

**Обоснование:**  
Целевая аудитория — не специалисты по охране. Технические термины вызывают непонимание и панику. Ключевая ценность — прозрачность без паники.

## DEC-003: Тройное кодирование статуса охраны

**Дата:** —  
**Связь с PRD:** SEC-03, a11y  
**Решение:** Статус всегда = цвет + иконка + текстовая метка.

**Обоснование:**  
Аудитория включает пожилых. Часть пользователей может иметь нарушения цветового восприятия. Одного цвета недостаточно — WCAG и здравый смысл.
