# Ролевая модель — Reforce

> Источник: PRD v3.2, раздел 4.3 и 6.0

---

## Принцип разделения мастерства

| Система | Мастер-данных | Управляет |
|---|---|---|
| **ЛК (Reforce)** | Пользователи и роли | Аккаунты, аутентификация, бизнес-роли |
| **Securige** | Охранные данные | Пользователи прибора, пинкоды, зоны, события |

**Связь:** ЛК → Securige: «назначить пользователя X на объект Y с ролью Z»  
Securige → ЛК: статусы, события, конфигурация

---

## Иерархия ролей

```mermaid
graph TD
  OWNER[Владелец объекта\nПолный доступ]
  ADMIN[Администратор компании\nВсе объекты организации]
  
  ADMIN --> REGIONAL[Региональный менеджер\nОбъекты региона]
  REGIONAL --> MANAGER[Менеджер объекта\nКонкретный объект]
  MANAGER --> GUARD[Пользователь охраны\nПостановка/снятие]
  MANAGER --> OBSERVER[Наблюдатель\nТолько просмотр]
  OWNER --> GUARD
  OWNER --> OBSERVER
  
  RESP[Ответственное лицо\nОповещение при инцидентах]
  GUEST[Гость / Техник\nВременный доступ]
```

## Жизненный цикл пользователя

```mermaid
stateDiagram-v2
  [*] --> Посетитель: заходит на сайт
  Посетитель --> Зарегистрированный: регистрация через OIDC
  Зарегистрированный --> Клиент: подписан договор
  Клиент --> Пользователь_охраны: подключён на пульт
  Пользователь_охраны --> Приостановленный: договор на паузе 1-6 мес.
  Приостановленный --> Пользователь_охраны: реактивация
  Пользователь_охраны --> Неактивный: расторжение
  Неактивный --> Пользователь_охраны: win-back через 1/3/6 мес.
```
