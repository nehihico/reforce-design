# DS: Дизайн-принципы — Reforce

> Адаптация из Ant Design 10 принципов + ценности бренда Reforce v5.  
> Применяется ко всем продуктам: reforce-lk, reforce-market, панель управления, ARM.

---

## Ценности (почему мы так делаем)

Основаны на позиционировании v5: «платформа, не охранная компания».

| Ценность | Смысл для дизайна |
|---|---|
| **Спокойная уверенность** | Интерфейс не запугивает и не нагнетает — статусы информируют, а не тревожат |
| **Контроль у пользователя** | Критичные действия требуют подтверждения; обратная связь — немедленная |
| **Простота сложного** | Охрана объекта — одно касание. Сложность скрыта, а не устранена |
| **Доверие через консистентность** | Одинаковое поведение в каждом сценарии снижает тревогу |

## 10 операционных принципов

### 1. Близость (Proximity)
Связанные элементы располагаются рядом. Несвязанные — разделены.  
**Пример:** статус объекта и кнопка управления — в одном блоке, а не разбросаны по экрану.

### 2. Выравнивание (Alignment)
Все элементы выровнены по общей сетке. Нет произвольных отступов.  
**Пример:** иконки, тексты и кнопки — на одной вертикальной оси в списке.

### 3. Контраст (Contrast)
Важное отличается от неважного визуально. Цвет, размер, насыщенность — инструменты иерархии.  
**Пример:** красный `#D42B2B` только для основного CTA и тревоги — не для декора.

### 4. Повторение (Repetition)
Один компонент = одно поведение везде. Кнопка «Поставить на охрану» всегда выглядит одинаково.  
**Пример:** все карточки объектов — одна структура, независимо от экрана.

### 5. Прямое действие (Make it Direct)
Взаимодействие происходит там, где находится контент. Минимум модальных окон.  
**Пример:** статус меняется прямо на карточке объекта, без перехода на отдельный экран.

### 6. Оставайся на странице (Stay on the Page)
Не уводи пользователя туда, откуда он не ждёт. Боттомшиты и inline-действия вместо навигации.  
**Пример:** подтверждение снятия с охраны — боттомшит, а не отдельный экран.

### 7. Лёгкость (Keep it Lightweight)
Меньше элементов = больше внимания к важному. Каждый элемент оправдывает своё существование.  
**Пример:** на главном экране ЛК — только статус и быстрые действия, не весь функционал.

### 8. Приглашение (Provide an Invitation)
Интерактивные элементы сигнализируют о возможности действия до касания.  
**Пример:** кнопки имеют hover/active-состояния; свайп-жесты имеют визуальный хинт.

### 9. Переходы (Use Transition)
Анимация объясняет изменения состояния. Переход помогает понять, что произошло.  
**Пример:** при постановке на охрану статус-иконка анимируется, не просто меняет цвет.

### 10. Мгновенная реакция (React Immediately)
Любое действие пользователя вызывает отклик не позднее 100ms (визуальный фидбек).  
**Пример:** кнопка меняет состояние сразу при касании, даже пока запрос ещё идёт.

## Запреты

| Нельзя | Почему |
|---|---|
| Использовать красный для декора | Красный = действие или тревога. Обесценивает сигнал. |
| Писать «тревога», «срабатывание», «ложная тревога» | Создаёт панику. Используем нейтральные формулировки. |
| Строить интерфейс только на цвете | Тройное кодирование: цвет + иконка + текст (a11y, пожилые пользователи). |
| Скрывать критичные действия | Пользователь должен понимать последствия до нажатия. |
| Делать tap-зоны меньше 44×44px | Минимум по WCAG и платформенным гайдлайнам Apple/Google. |

## Применение

Перед проектированием нового экрана или компонента — проверь по чеклисту:

- [ ] Соответствует ли расположение элементов принципам близости и выравнивания?
- [ ] Использован ли контраст для выделения главного?
- [ ] Нет ли лишних переходов между экранами (можно обойтись боттомшитом)?
- [ ] Есть ли немедленный визуальный отклик на действие?
- [ ] Работает ли интерфейс без цвета (скринридер, ч/б экран)?
