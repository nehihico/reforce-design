# Directive: Генерация описаний wireframes

## Когда использовать
После утверждения sitemap. Перед передачей в Figma. Описываю структуру экранов текстом.

## Процесс

1. Прочитай `ia/sitemap.md` и `ia/user-flows.md`
2. Для каждого приоритетного экрана (Must → Should) опиши структуру
3. Зафиксируй в `execution/screens.md`
4. Выдели edge cases для каждого экрана → `handoff/edge-cases.md`

## Формат описания экрана

```markdown
### [Название экрана]
**Платформа:** мобайл / веб
**Роль:** какая персона использует
**Trigger:** откуда попадает пользователь

**Компоненты (сверху вниз):**
- Header: ...
- Основной контент: ...
- Действия (CTA): ...
- Навигация: ...

**Состояния:**
- Default: ...
- Loading: ...
- Empty: ...
- Error: ...

**Edge cases:**
- Что если объектов нет?
- Что если Securige недоступен?
```

## Принципы для Reforce

- Простота > функциональность: каждый экран понятен без инструкции
- Mobile-first: основные действия доступны одной рукой
- Tap-зоны ≥ 44px (аудитория включает пожилых)
- Статус охраны — всегда виден без скролла
- Критичные действия (тревожная кнопка) — недвусмысленны, защищены от случайного нажатия
- Язык без паники: «направили группу реагирования», не «ТРЕВОГА»
