# Directive: Быстрое конкурентное исследование

## Когда использовать
В начале проекта или при работе над новым модулем. Цель — не изобретать велосипед, найти паттерны.

## Процесс

1. Определи фокус исследования: какой конкретный flow или паттерн изучаем
2. Выбери 3-5 конкурентов / аналогов (прямые + косвенные)
3. Для каждого заполни шаблон ниже
4. Синтезируй инсайты в конце файла

## Структура файла `research/competitive_analysis.md`

```markdown
## [Конкурент / аналог]
**Категория:** прямой конкурент / косвенный / паттерн из другой индустрии
**Фокус:** что изучаем (онбординг, статус объекта, уведомления)

**Что делают хорошо:**
- ...

**Что делают плохо / ограничения:**
- ...

**Паттерн для заимствования:**
- ...
```

## Для Reforce — источники вдохновения из PRD

- **Тинькофф** — «банк внутри приложения», упрощение сложного
- **Яндекс Такси** — сложный сервис через простой интерфейс
- **UX паттерны:** уведомления об инцидентах (как у банков — без паники)
- **B2B управление:** Jira, Linear — для мультиобъектного дашборда

## Что НЕ делать

- Не копировать без адаптации к контексту охраны
- Ring, Bosch, SimpliSafe — зарубежные, не применимы в РФ без учёта 152-ФЗ и RuStore
- Не изучать зарубежные аналоги без учёта российского регулирования (152-ФЗ, RuStore)
