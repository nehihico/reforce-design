# Directive: Передача разработчикам (Handoff)

## Когда использовать
После утверждения дизайна, до начала разработки. Цель — разработчики не должны гадать.

## Процесс

1. Прочитай `execution/screens.md` и `execution/decisions.md`
2. Заполни `handoff/specs.md` по структуре ниже
3. Заполни `handoff/edge-cases.md` — все нетипичные состояния
4. Проверь: все ли интеграции из `prd.md` раздел 8 задокументированы?

## Структура `handoff/specs.md`

```markdown
## [Название экрана / компонента]
**Figma:** [ссылка на фрейм]
**Платформа:** мобайл / веб
**API:** какие эндпоинты использует

### Поведение
- Что происходит при нажатии X
- Что происходит при получении данных Y

### Состояния
- Loading: показываем skeleton / spinner
- Empty: [текст] + [CTA]
- Error: [текст ошибки] + [кнопка повтора]

### Анимации
- Длительность: 200ms / 300ms
- Easing: ease-in-out

### Токены
- Цвет фона: --color-bg-primary
- Размер текста: --text-body-1
```

## Для Flutter-разработчиков (Reforce)

- Указывай breakpoints для адаптива
- Offline-поведение: что кэшируется, что блокируется
- Push-уведомления: какой тип (критический/информационный/маркетинговый)
- Securige API: какие данные нужны, какой fallback при недоступности
- Tap-зоны ≥ 44px — отдельно указывай для каждого интерактивного элемента

## Что НЕ включать в handoff

- Обоснование дизайн-решений (это в `execution/decisions.md`)
- Технические детали backend (это не твоя зона)
- Пожелания (только конкретные требования)
