# Directive: UX-аудит

## Когда использовать
После получения реализованного продукта. Сравниваю с исходным дизайном и брифом.

## Процесс

1. Прочитай `brief.md`, `execution/screens.md`, `handoff/specs.md`
2. Сравни реализацию с дизайном по чеклисту ниже
3. Зафиксируй расхождения в `audit/compliance.md`
4. Заполни `audit/metrics.md` количественными данными

## UX-чеклист

### Навигация
- [ ] Все экраны из sitemap присутствуют?
- [ ] Навигация между разделами работает корректно?
- [ ] Возврат назад предсказуем?

### Контент и текст
- [ ] Язык соответствует tone of voice (без технических терминов)?
- [ ] Все состояния (empty, error, loading) реализованы?
- [ ] Сообщения об ошибках понятны пользователю?

### Взаимодействие
- [ ] Критичные действия защищены от случайного нажатия?
- [ ] Feedback на действия (haptic, анимация, звук)?
- [ ] Время отклика: постановка/снятие ≤ 2 сек?

### Accessibility
- [ ] Tap-зоны ≥ 44px?
- [ ] Контрастность текста соответствует WCAG AA?
- [ ] Работает с увеличенным шрифтом системы?

### Offline
- [ ] Последний известный статус кэшируется?
- [ ] Показывается ли состояние «нет связи»?

## Метрики для `audit/metrics.md`

**Количественные:**
- Время до первого ключевого действия (постановка/снятие)
- Количество нажатий до цели
- % успешных авторизаций с первой попытки
- Время загрузки экрана объектов

**Качественные:**
- Понятность без инструкции (оценка 1-5)
- Доверие к статусу (оценка 1-5)
- Соответствие ожиданиям пользователя (оценка 1-5)
