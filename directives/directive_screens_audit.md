# Directive: Аудит экранов

## Когда использовать
После завершения дизайна экранов. Перед передачей в разработку или после получения реализации.

## Процесс

1. Прочитай `brief.md` и `prd.md` — зафиксируй исходные требования
2. Прочитай `execution/screens.md` — список запроектированных экранов
3. Для каждого Must-have требования из PRD проверь: есть ли экран/решение?
4. Заполни `audit/compliance.md`

## Чеклист на каждый экран

- [ ] Соответствует user flow из PRD?
- [ ] Все состояния описаны (default, loading, empty, error)?
- [ ] Edge cases учтены?
- [ ] Tap-зоны ≥ 44px?
- [ ] Текст понятен без инструкции?
- [ ] Нет технических терминов (шлейф, зона, пинкод)?
- [ ] Работает в offline-режиме (или показывает корректное состояние)?
- [ ] Поведение при ошибке Securige определено?

## Шкала соответствия

| Балл | Значение |
|---|---|
| 5 | Полное соответствие брифу |
| 4 | Незначительные отклонения |
| 3 | Есть расхождения, не критичные |
| 2 | Существенные отклонения от брифа |
| 1 | Не соответствует брифу |

## Результат

Заполни `audit/compliance.md` с итоговым баллом и списком расхождений.
